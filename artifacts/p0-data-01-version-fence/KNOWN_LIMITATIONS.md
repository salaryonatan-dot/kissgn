# KNOWN LIMITATIONS — recorded, not hidden

1. **Old page display after activation.** An old tab keeps its listener; after activation it receives a V2 node its generic reader does not understand (VF-26 negative control). Every write it can emit is denied; data is safe; UX is a reload. Not fixable server-side for JS already running.
2. **Rules cannot verify integer-ness** of `policyRevision`/`minStorageProtocol` (`isNumber()` only). The tooling (only writer) and the parser enforce safe integers; a privileged writer could still store `1.5` — which the parser treats as malformed (fail closed for clients), while Rules would accept the record as VALID. Contained: no client path can write the record.
3. **Admin bypasses Rules.** "Conversion only in quiesced", "one operation at a time" and "no v2_active→legacy" are application-level invariants of `tools/storage-v2/policy.mjs`. A wrong privileged write (VF-11/VF-25 simulate a bad `legacy` record over a V2 node) does NOT reopen legacy writes — Rules still require a V2-shaped result on a V2 node — but it blocks compatible clients (`v2_without_policy`) until corrected. Runbook: use the wrapper, never `upgradeBusinessToV2` directly.
4. **`api/admin.js` gates admission only.** A request admitted just before `quiesce` may still commit; quiescence must drain in-flight server work operationally (documented in the endpoint comment). The entry-exception handlers (`set-entry-exception` / `clear-entry-exception` → `lib/repositories/entryExceptionsRepo.js`) are the only Admin-SDK server path that mutates a business's entries-domain ledgers; the other Admin writes (`api/admin.js` tenant/user/client management, proactive digests and index) do not touch the entries domain and are not gated.
5. **`minStorageProtocol` is advisory** for honest clients only; enforcement is shape × phase. A dishonest new client gains nothing beyond what a compatible client may do.
6. **Rows-map whole deletion residual** (tracked since the core): unchanged; a last-row delete still needs it.
7. **Client gate race**: a policy change between the client gate and the server commit yields a server denial surfaced as `rules_rejected`/`failed` (never "saved"); the client cannot pre-empt it and does not claim to.
8. **Server readers are policy-agnostic by design** (Admin reads, no writes); the server-reader matrix and its fixtures are unchanged and green.
9. **Pre-cutover blockers remain** (out of scope, listed in the final report): production preflight, protected backup, rollback boundary definition, one-business canary.
