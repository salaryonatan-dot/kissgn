# DECIMAL DOMAIN DECISION — server readers R2

**Numeric domain (Codex, `~/Documents/marjin-reviews/2026-09-24/deterministic-decimal-design/NUMERIC_DOMAIN.md`): MIXED_UNDEFINED.** Manual entries carry Numbers and numeric strings of variable scale and sign; no enforceable two-decimal (cents) contract exists anywhere in the repository (`NUMERIC_DOMAIN.md`, `ARITHMETIC_OPTIONS.md`). Fixed-cents quantization, sorting, Kahan and pairwise summation were all rejected by Codex; permutation invariance over the existing per-row values is the requirement.

**CTO D-R2-1 — per-row semantics PRESERVED.** `num` (`Number(v) || 0`), `sumObj`, `rowComponents` (revenue = sales+deliveries+other_income; foodCost = Σsupplier_payments ‖ food_cost; laborCost = payroll + Σhourly_payroll) are byte-identical to R1. No monetary value is recomputed from raw fields; no rounding is introduced. The R2 change starts exactly where two or more per-row component Numbers of one business date are accumulated. A single row passes its component Numbers through unchanged (`decimalSum([x]) === x`), so singleton and unique-date results are bit-identical to R1 — including the in-row binary residuals (`0.1 + 0.2` inside one row stays `0.30000000000000004`; the supplier-map residual `0.1+0.2−0.3` stays a truthy tiny number, so the `food_cost` fallback is not taken), as proven by the "singleton passthrough" test.

**CTO D-R2-2 — intermediate overflow corrected.** Accumulation is exact, so an operand order that would have overflowed to `Infinity` in binary (`[1e308, 1e308, −1e308]`) now yields the exact finite total `1e308` for every permutation. No clamp, no monetary limit, no rounding, no new input acceptance: a final exact total beyond the finite range converts to `±Infinity` exactly as the existing Number output representation dictates (`[MAX_VALUE, MAX_VALUE] → Infinity`). Non-finite categories keep their meaning (`OVERFLOW_POLICY.md`).

**Where the boundary lies (Codex "smallest compatible boundary", adopted verbatim):** exact for the canonical decimal representations of the existing per-row component Numbers; not exact for arbitrary source strings, not a correction of arithmetic inside a row, not a nested-map member permutation invariant. Those wider interpretations were explicitly not implemented (recorded as follow-ups in `DOWNSTREAM_EQUIVALENCE.md`).

**Runtime scope:** `src/repositories/analytics/dailyMetricsRepo.ts` only; helper kept private to the module (no shared financial utility, no dependency).
